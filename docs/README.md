# Документация сервиса классификации обращений

Проект умеет преобразовать Word-справочник тематик в нормализованные JSON,
построить локальные BM25/FAISS-индексы, извлечь текст из PDF через
мультимодальную LLM и выполнить классификацию обращения по темам, виду вопроса
и subtype.

## Текущий результат

На 18 июля 2026 года в проекте подготовлены:

- классификатор редакции `2025-10-31`;
- 2 094 валидных узла и 1 220 leaf-тематик;
- BM25-индекс и FAISS-индекс на 1 220 тематик;
- русский препроцессинг через `razdel` и `pymorphy3`;
- anchor-based генерация retrieval-запросов через `retrieval_topic_anchors.json`;
- синхронный pipeline выбора тематик, вида вопроса и subtype;
- отдельный `typeDecisionText` для выбора вида вопроса и subtype;
- официальный JSON-справочник из 39 subtype-записей;
- offline evaluation с resumable predictions, метриками и confusion matrix;
- FastAPI для классификации текста и PDF, health/readiness и web-страницы;
- OCR PDF через мультимодальную LLM по Hydra/OpenAI-compatible API;
- Pydantic-схемы результата и итоговая валидация;
- CLI для импорта, построения индексов, retrieval и классификации;
- набор unit/smoke-тестов для программных контрактов.

Текущий рабочий реальный набор — `data/evaluation/real_v3.json` на 16
размеченных документах после OCR через мультимодальную LLM. Последний полный
прогон показывает сильный retrieval и более стабильный выбор вида вопроса, но
subtype остаётся самой слабой частью.

После очистки путей раздела `0005` BM25/FAISS-индексы перестроены и согласованы
с `themes_leaf.json` через `themesSha256`; production `/ready` должен возвращать 200
при доступных локальных артефактах.
