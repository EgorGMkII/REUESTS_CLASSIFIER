## Тестовое покрытие

На момент последнего обновления проходит 71 тест, суммарное line coverage
контролируемых модулей — не менее 85%:

- код и иерархия классификатора;
- Word-text parsing на искусственном фрагменте;
- нормализация и русская токенизация;
- BM25, vector и hybrid retrieval на небольшом справочнике;
- question type/subtype fallback;
- защита theme selector от посторонних кодов и дублей;
- итоговые валидаторы;
- координация pipeline и отсутствие кандидатов.

Это хорошее покрытие программных контрактов, но не доказательство качества
классификации: LLM в тестах замокан, а retrieval проверяется на искусственном
наборе.

Текущий `themes_leaf.json` очищен от ошибочного заголовка раздела `0005`.
FAISS/embeddings перестроены, а `index_report.json` содержит актуальный
`themesSha256`, поэтому API считается готовым при доступных локальных артефактах.

Для retrieval добавлен `data/classifiers/retrieval_topic_anchors.json`. Модель
сначала выбирает тематический якорь и центральный предмет обращения, затем
формирует несколько retrieval queries. Первый query обязан отражать главный
предмет обращения языком справочника, остальные query — дополнительные углы
поиска.

Для выбора вида вопроса добавлен `typeDecisionText`: отдельная выжимка, где
сохраняются административные признаки документа, просьба автора и различение
`2 Заявление`, `3 Жалоба`, `5 Запрос информации`, `7 Запрос прокуратуры`.

## Что намеренно отсутствует

- LangGraph и agent/tool calling;
- асинхронные очереди;
- база данных;
- обучение собственной ML-модели.

Старый локальный PaddleOCR-контур оставлен только как лабораторный инструмент в
`tools/ocr_lab`. Docker/API runtime использует мультимодальную LLM OCR.
